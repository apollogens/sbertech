## Карточка A1: частичное объединение и усреднение суточных прогнозов

**Проблема и представление.** Для нижнего ряда i предсказать ежедневные продажи `y[i,t+h]`, h=1…28. Группа g(i) определяет набор рядов для общего дерева. Три семейства групп: магазин, магазин×категория, магазин×отдел; в каждом применяются два способа генерации горизонта.

**Формула выхода.** `forecast[i,h] = sum(family[k,i,h] for k=1…6)/6`. Здесь нет целевой переменной недельного объёма, нет матрицы MinTrace и нет гарантии, что независимо прогнозируемые агрегаты согласованы: независимо прогнозируемых верхних итогов в этом выходе вообще нет.

**Входы.** Идентификаторы item/dept/category, суточная сетка, известный календарь, SNAP, события, недельные цены. Preprocessing убирает даты до release, определённого по первой доступной цене. Строятся price max/min/std/mean и отношения, лаги 28…42, сдвинутые на 28 дней rolling mean/std на 7/14/30/60/180, а также краткие динамические rolling при shift 1/7/14. Категориальные mean/std encodings в данном файле используют маску `sales[d > 1913] = NaN`; это фиксированная граница конкретного конкурса, которую необходимо пересчитывать для каждого cutoff.

**Обучение.** LightGBM Tweedie power=1.1. В проверенной рекурсивной store-ветви learning_rate=.015, num_leaves=2047, min_data_in_leaf=4095, n_estimators=3000; в нерекурсивной store-ветви num_leaves=min_data_in_leaf=255. Поэтому общее описание «все модели с одинаковыми параметрами» неверно. Именованные private/public/cv-интервалы заданы числами M5. Рекурсивная validation-маска входит в train — это логирование на части обучающих данных, не независимый контроль.

**Инференс.** Рекурсивная ветвь проходит дни 1…28, пересчитывает rolling-признаки и записывает прогноз обратно в временный столбец sales, делая его доступным для следующих дней. Ошибка может накапливаться. Нерекурсивная ветвь читает заранее созданные безопасные для 28-дневного горизонта лаги и получает прогнозы без заполнения будущей фактической продажи. При 64 днях лаг 28 уже недостаточен для полного прямого горизонта: простая замена 28 на 64 в цикле приведёт к недоступным признакам.

**Организация.** `3. code/1. preprocessing`, `2. train`, `3. predict`; по три файла каждого типа. Последний `3-1. Final ensemble.py` объединяет шесть csv по id. Каталог в нём называется `6. submissions`, а в части остальных файлов/README — `6. submission`: пути требуют проверки. README ссылается на 220 сохранённых моделей, но в текущем git-снимке A1 лежат заглушки вместо готового набора. Старое `verbose_eval` в вызове `lgb.train` несовместимо с фактической установленной сигнатурой LightGBM 4.7.0.

**Сложность и минимальная проверка.** Цена обучения пропорциональна суммарному числу наблюдений во всех шести наборах и числу деревьев; рекурсивный инференс дополнительно требует 64 последовательных обновления признаков после адаптации. Численные бюджетные обещания без запуска не делаются. Самая небольшая содержательная Nonton-проверка — одна дополнительная модель warehouse×category с теми же legal origins и ограниченной сложностью; сравнить standalone с глобальной моделью, затем только при дополнительном сигнале простое среднее. Это меняет pooling, но сохраняет дневную регрессию и поэтому не является главным кандидатом представления.

**Граница доказательства.** Официальное первое место и исходники подтверждены; сами прогнозы не воспроизведены. Лицензия исходника отсутствует: спецификация идеи допустима для самостоятельной разработки, копирование блоков в проект не выполнялось.

## Карточка U1: нормализованная регрессия квантилей с прямым горизонтом

**Проблема.** Предсказать `Q_q(y[i,t+h] | history,calendar)` для девяти q и 28 h, на всех уровнях иерархии. Потеря `rho_q(u)=max(q*u,(q-1)*u)`, масштабирование по исторической изменчивости и весам продаж. Оптимум такого функционала не равен условному среднему, необходимому, например, для квадратичной ошибки.

**Фактически реализованные компоненты.** `aggTrain` строит 12 уровней сумм продаж. Нижние ряды дополнительно делятся по категориям. Из истории извлекаются ewm, rolling mean/median/std/skew/kurt и квантильные статистики; доля ненулевых дней — явный признак. Признаки времени t сочетаются с `days_fwd`; label берётся в `future_d=t+days_fwd`. `getSubsample` случайно выбирает горизонт 1…28 и перевзвешивает вероятность попадания рядов, затем `getXYG` нормализует y и некоторые признаки по trailing variability со случайным масштабным возмущением. Нельзя объявлять это случайным разбиением forecast-строк: sampling обучающих примеров и разделение оценочных периодов — разные операции.

**Точная версия существенна.** Original notebook использует `TIME_SEED=True`, seed из микросекунд часов и отдельную ручную настройку LEVEL/QUANTILES; это мешает побитовой воспроизводимости. Replication-файл содержит SPEED, SUPER_SPEED, REDUCED_FEATURES и другой объём sampling/число деревьев. Активное значение `SPEED=False`, поэтому читать README о быстром запуске как фактическую конфигурацию файла неверно. `VALIDATION=-1` отключает исключение конкретного года; наличие комментария про pure holdout не означает автоматически активный holdout. Для Nonton обязателен отдельный временной протокол.

В original `runQBags` строит out-of-fold прогнозы, исключая из fit строки с тем же годом целевой даты (`groups != group`), и обучается на остальных годах. Такое исключение года не гарантирует обучение только на прошлом относительно каждой оцениваемой даты: для раннего года могут использоваться более поздние. Это способ cross-learning в историческом корпусе, а не готовый rolling-origin протокол Nonton. В этой работе он не использовался для доказательства будущей точности.

**Постобработка.** В replication предусмотрена мультипликативная коррекция прогнозов уровней ≤9 через отношение среднего горизонтового профиля уровней к собственному; `ADJUSTMENT_FACTOR=.7` для медленного варианта и 1 для SPEED. Это специальная коррекция, а не доказанная MinTrace-проекция и не математическая гарантия аддитивности квантилей.

**Что можно перенести.** Нормализация по доступной истории и плотность ненулевых дней — проверяемые признаки для Nonton. Сама многоуровневая квантильная задача, известные future-calendar covariates M5 и 45 ручных тренировок не нужны Nonton submission. Минимальный опыт: одна независимая нормализация/характеристика occurrence в уже законном протоколе; полное U1 отложить. Изменение среднего на медиану не лечит разреженность автоматически.

**Граница доказательства.** Изучены код и README; обещания 20× ускорения/1% ошибки не проверены. Публичная лицензия A1/U1 не найдена. Исходные pkl не десериализовались, исходный WSPL не пересчитывался.

## Карточка Favorita: три способа прямого многогоризонтного обучения

**Представление.** Логарифм неотрицательной продажи. Историческое окно, promo и статические признаки → вектор из 16 будущих log-sales. LGBM реализует 16 отдельных регрессоров; CNN даёт Dense(16, relu); GRU строит выходы decoder. Итоговый обратный переход в `make_submission` — `clip(expm1(pred),0,1000)`. Верхняя граница 1000 специфична этому коду и не является универсальным правилом.

**Источник сигнала.** Promo-матрица включает будущие значения, которые официально даны в Favorita. В CNN есть отдельные ветви причинной свёртки и Dense обработки истории, embeddings категорий, future promo; decoder GRU принимает календарные и промо-признаки, состояние encoder проходит Dense connector. MSE на log1p соответствует логарифмическому конкурсу, но не минимизирует одновременно SMAPE/WAPE/Bias Nonton.

**Разделение.** LGBM использует 14 начал через семь дней назад от 05.07.2017, validation начинается 26.07, final 16.08. В neural generator выбираются исторические origins. Важно: фильтр рядов `max(sales[2017-01-01…2017-08-15])>0` в исходнике глобален относительно июльского holdout; он способен использовать будущую активность для отбора ряда. Такую процедуру нельзя переносить на Nonton backtest. Точечные features и series filtering обязаны быть вычислены из данных не позже origin.

**Воспроизводимость.** MIT разрешает модификацию с сохранением copyright/лицензии, но запуск не готов без ремонта: `best_rounds` закомментирован перед `.append`, используются `pd.datetime`, старые Keras `fit_generator`/CuDNNGRU, не зафиксирован полный стек. Скрипты ссылаются на подготовленные feather и локальные файлы. Итоговые веса ансамбля README не превращены в единый воспроизводимый pipeline. Никакие изменения в upstream не выполнялись.

**Минимальная проверка Nonton.** Концепцию прямого многогоризонтного выхода лучше проверять в поддерживаемой реализации N-HiTS/TiDE, а не ремонтировать весь legacy Keras ради 16-дневного решения; это архитектурный выбор, не заявление об эквивалентности методов. Если признаков будущих промоакций нет, они исключаются. Гарантии сохранения общего 64-дневного объёма у исходной CNN нет.

## Проверенная совместимость и решение о повторном использовании

В `.venv` фактически проверены LightGBM 4.7.0, NumPy 2.5.4, pandas 3.0.6, SciPy 1.18.1; scikit-learn/TensorFlow/Keras не установлены. Проверка сигнатуры `lgb.train` показывает callbacks вместо старого `verbose_eval`; `hasattr(pd,'datetime')` ложно. Это проверка API без запуска внешних моделей. Ссылки на отсутствующие зависимости в чужом коде не приводят к автоматической установке в production.

Решение: не включать M5 A1/U1 исходники в поставку; Favorita допускает перенос с MIT-уведомлением, но технически переносить полный legacy pipeline нецелесообразно. Обоснованные идеи фиксируются независимо. Для изменения представления приоритет имеют недельный объём с дневным распределением и дешёвый агрегатный прогноз с согласованием. Их эффективность должен установить только Nonton-эксперимент; M5 не является доказательством ни одной из этих двух конкретных реализаций.
