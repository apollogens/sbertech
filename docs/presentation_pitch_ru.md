# Материал для защиты: Nonton Forecasting

## 1. Задача и входные данные

«Мы прогнозируем наблюдаемые продажи на 64 дня по складу и товару. Проверили 1 492 370 строк продаж и 6 153 988 строк остатков. Каталог включает 11 складов и 799 товаров. Результат — CSV из 562 496 строк с прогнозом на 2026-08-01–2026-10-03».

Показать: требования хакатона, `reports/data_audit.md`, `submission.csv`. Дата прогноза определяется концом исторического файла, а не датой презентации.

## 2. Что выяснилось при аудите

«В исходных остатках есть 57 отрицательных значений и 804 588 конфликтующих дневных ключей. Мы удаляем отрицательные записи и все оставшиеся неоднозначные ключи; отсутствие остатка сохраняем как missing. Департаменты суммируем. Отсутствующую запись продажи считаем нулевой наблюдаемой продажей — это явное допущение, а не восстановление скрытого спроса».

«Встроенный scorer исключает дни, где факт и прогноз равны нулю, хотя текстовая формула SMAPE описывает их иначе. Мы сохранили исходный scorer и проверили соответствие своей реализации. Итоговый каталог используем полный: размер в регламенте требует ещё 12 пар, не наблюдавшихся в продажах».

Показать: `docs/assumptions_and_conflicts.md`, `reports/detailed_audit.json`, metric tests. Сырые неоднозначные stock не выдавать за допустимый API-вход: подготовка файлов выполняется явно.

## 3. Проверка без утечки будущего

«Использованы три последовательных временных окна по 64 дня. Первые два выбирают objective и порог; третье открывается после фиксации выбора. Все признаки видят только историю до origin, все обучающие labels известны к cutoff. Изменение будущих sales и stock не меняет прошлые признаки — это проверено тестами».

Показать origins 2026-01-20, 2026-03-25, 2026-05-28 и `selection_frozen.json`. Последнее окно — 2026-05-29–2026-07-31. Каталог идентификаторов фиксирован по предоставленной организаторами выборке; качество появления неизвестных товаров этим опытом не проверено.

## 4. Модель и сравнение

«Проверены шесть простых baseline, LightGBM L2 и Tweedie, для бустинга — фиксированные пороги 0, 0.25 и 0.5. Выбрана одна глобальная Tweedie-модель с 220 деревьями и порогом 0.25. Она использует 45 признаков истории, календаря, склада, товара и наблюдаемости остатков. Один регрессор получает horizon; предыдущие предсказания не подаются обратно».

| Кандидат | Средний локальный score окон выбора |
|---|---:|
| Tweedie, порог 0.25 | 0.832383 |
| L2, порог 0.25 | 0.833767 |
| TSB | 0.854395 |
| Среднее 90 дней | 0.859621 |
| Последнее значение | 1.000000 |

«Разница Tweedie и L2 мала, и на втором окне L2 немного лучше. Это основание сохранить лучший зафиксированный кандидат, но не заявлять универсальное превосходство Tweedie. Локальный score нормирован по last-value и не является местом в конкурсном рейтинге».

## 5. Честный результат на holdout

| Метрика | Выбранная модель | TSB |
|---|---:|---:|
| Официальный SMAPE, % | 158.69 | 178.52 |
| WAPE, % | 80.43 | 88.28 |
| RMSE | 0.86628 | 0.87248 |
| Средний абсолютный Bias, % | 80.57 | 66.15 |
| RMSLE | 0.31262 | 0.30556 |
| Локальный score | 0.838184 | 0.862795 |

«Модель улучшает выбранный совокупный критерий, SMAPE, WAPE и RMSE относительно TSB, но проигрывает ему по Bias и RMSLE. Порог уменьшает малые ложноположительные прогнозы ценой Bias. WAPE около 80% означает, что точность остаётся ограниченной. На разреженных рядах WAPE около 103%, поэтому готовность к автоматическим закупкам без дополнительной проверки не заявляем».

## 6. Что происходит на дальнем горизонте

«На holdout WAPE растёт с 78.85% для дней 1–14 до 82.66% для последних восьми дней; RMSE — с 0.81620 до 0.90082. Direct-модель устраняет возврат собственных ошибок в признаки, но не неопределённость дальнего будущего. Календарь и недельная история учитывают сезонность; причины остаточного ухудшения отдельно не установлены».

«Низкий SMAPE короткой последней восьмидневки нельзя сравнивать с 64 днями как доказательство улучшения: scorer сильнее учитывает полностью нулевые короткие серии. Смотрим одновременно на WAPE, RMSE и разрезы».

Показать: `reports/segment_metrics.csv` и таблицы `reports/model_selection.md`. Diagnostic на 180-дневном входе совпал по метрикам на одном origin; не обобщать на все возможные входы.

## 7. Воспроизводимость и сервис

«Финальное обучение заняло 25.53 с, inference готовой панели — 3.48 с, размер модели — 1.33 MB. Сервис использует тот же код признаков и сохранённый артефакт, а не обучает модель на запросе. Offline и API дали совпадающие ключи всех 562 496 строк; максимальное отличие 3.55e−15 при допуске 1e−7. Повторные POST вернули одинаковые байты».

«POST на полном подготовленном входе занял 33.53 с; GET CSV — 1.29 с, GET JSON — 0.93 с. Это измерения конкретного запуска в текущем окружении. Docker-сборку и контейнерные ограничения подтверждаем только отдельным фактически выполненным контейнерным тестом».

Контейнер проверен отдельным полным HTTP POST с `--network none`: сборка без кэша слоёв заняла 56,13 с, POST — 33,89 с, пик cgroup memory — 2,43 GB. Все 562 496 строк совпали с offline в пределах 3,55e−15. Полный GET JSON и повторные POST проверены локально; отдельный контейнерный повтор JSON не выполнялся.

Показать: `reports/parity_benchmarks.json`, `reports/training_benchmarks.json`, `reports/container_benchmark.json`, API `/health`, фильтрацию `/predict`, полный `/predict/all`. Актуальный окончательный статус — `reports/final_verification.md`.

## Ответы на вероятные вопросы

- **Почему не ансамбль или нейросеть?** В измеренном сравнении достаточно одного воспроизводимого бустинга; дополнительная сложность пока не обоснована опытом.
- **Почему не 64 отдельных модели?** Один регрессор использует общий исторический сигнал и horizon; обучаются восемь опорных горизонтов, проверяются все 64.
- **Можно ли назвать результат точным прогнозом скрытого спроса?** Нет, цель — наблюдаемые продажи; отсутствующая продажа и отсутствие товара не дают однозначной оценки упущенного спроса.
- **Какой эффект в деньгах?** Не измерялся. Анонимизированные суммы не интерпретируем как реальные рубли, ROI не заявляем.
- **Что улучшать дальше?** Уточнить смысл конфликтов остатков с владельцем данных, проверить специализированную модель появления продаж для sparse-сегмента и новые временные окна. Эти варианты ещё не показали улучшение и не входят в заявленные результаты.
