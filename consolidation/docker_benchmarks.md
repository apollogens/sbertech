# Проверка финальных контейнеров

Оба образа исполнены без сети, с 4 CPU и лимитом 6 GiB. В таблице полная HTTP-операция: валидация CSV, загрузка истории, построение признаков, все необходимые Booster, alignment и сериализация. GET/JSON, повторный POST, сохранение кэша после ошибочного POST и пустой кэш после restart проверены.

| equal4 | 1.43GB | 147131116 | 21.868 | 20.934 | 4691660800 | 1.07e-14 |

Первичная сборка incumbent с `--no-cache`: 47.260 с. Это пересборка без reuse инструкционных слоёв, не измерение полностью холодного Docker daemon/диска/registry. Финальные сборки после peer review использовали cache; их отдельные timings — `docker_build_*_final.json`. Первоначальная сборка candidate до исправления config не выдаётся за проверенный финальный образ. Базовый Python закреплён digest, runtime packages — точными версиями.

`inspect.Size` и `docker image ls` в данном Docker Desktop используют различный учёт хранения; их нельзя смешивать для утверждения экономии. Ни одна из величин не приближается к лимиту 30 GB. cgroup peak включает процессы probe/CSV comparison, файловый cache и повторные запросы, а не только модель. Оба измерения укладываются в 64 GB RAM и лимиты POST 60 минут/GET 10 минут. Это последовательные acceptance measurements, не статистический latency benchmark. Исходные CSV поданы после старта; в образах их нет. Runtime images не содержат OOF/NPZ, тестовых библиотек и чужих checkout.
