# Проверка на входе из ровно 180 календарных дней

Использованы сохранённые исторические веса; нового обучения и подбора параметров нет. Для каждого origin sales и stock обрезаны до интервала [origin−179, origin] до построения панели. Stock внутри окна предварительно очищен src.data.clean_stock: удалены отрицательные остатки и все конфликтующие дубликаты; это прежняя политика repair исходного экспорта, а не тест приёма невалидных CSV публичным API. Membership вычисляется только по переданным sales, включая нулевые строки. Все 64 будущих дня используются исключительно как truth из сохранённой панели.

D/W/S/A/equal4 рассчитаны каноническими src.components и src.ensemble с теми же весами и threshold .25 после смеси. Загружены исторические TXT и проверены их hashes/features/cutoff. Исторические config отличаются от финального bundle отсутствием ensemble_contract: runner не объявляет их runtime-v2 release и не меняет исходные manifests. Прежние full-history NPZ пересчитаны теми же официальными функциями scorer. Среднее SMAPE — среднее smape_series, Bias — среднее bias_abs_series только по eligible рядам; полный квадратичный merge scorer не запускался.

Это повторно использованные окна, а не новый untouched test. Первые четыре origin — development, последний terminal — только диагностика. Разница 180/full-history смешивает эффект укороченной статистики и membership по входному окну; она не является чистым эффектом архитектуры. Модели обучены прежним full-history способом, поэтому это проверка serving-переноса готовых весов, а не новый rolling-180 training protocol.

Для incumbent повторный 180-day inference выполняется только при наличии однозначно привязанных сохранённых TXT на origin. Их полный перечень и пропуски фиксируются в coverage.csv. Прежний incumbent NPZ остаётся full-history reference; отсутствующие веса не подменяются финальной моделью.

## Вывод по одинаковому 180-дневному входу

Ансамбль equal4:P1 сохраняет небольшое улучшение всех пяти средних development-метрик относительно corrected D:P1: SMAPE 165.307454 → 165.027991; WAPE 85.931055 → 85.723702; RMSE 0.775274 → 0.771062; BIAS 82.795357 → 81.284307; RMSLE 0.307112 → 0.305680. Это сравнение на одних четырёх origins и одинаковом протоколе входа. Оно не доказывает превосходство над incumbent на всех четырёх 180-day окнах: исторические incumbent TXT однозначно доступны только на двух из них.

Разница с прежним full-history экспериментом мала и смешанная. Нельзя приписывать её cleanup кода: веса сохранены, но объём предоставленной истории изменён намеренно. Все full-history reference NPZ проверяются по origin/key hash и сохранённому SHA256. Отдельная проверка reference_validation.json подтвердила согласие пересчитанных official-метрик с прежним CSV: максимальная ошибка 5.69×10⁻¹⁴.
