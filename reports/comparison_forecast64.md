## Почему цифры SMAPE из README несопоставимы

У вас `src/metrics.py:38` исключает дни (факт=0, прогноз=0) из среднего внутри серии, сохраняя ноль для полностью нулевой серии. Это поведение опубликованного исполняемого scorer.

У внешнего решения `forecast-container/app/metrics.py:58` такие дни входят в среднее со значением 0. Это соответствует текстовой формуле ТЗ. Его комментарий ссылается на подтверждение судей; независимого подтверждения решения судей в доступных материалах нет. В локальном `markdown hakaton.md` текст и встроенный Python действительно расходятся.

Пример одной серии: факт `[1, 0]`, прогноз `[0, 0]`. Ваш scorer выдаст 200%, внешний — 100%. Поэтому 158,69% и 29,76% сами по себе не показывают величину улучшения.

### Воспроизведённые проблемы внешнего решения

- `quantity="oops"`: валидатор не вернул ошибок, настоящий TestClient POST вернул **200**, значение молча заменено нулём в `app/features.py:71`.
- `quantity=NaN`, `quantity=inf`, нечисловой `stock`, пустой article: отдельные валидаторы вернули пустой список ошибок. Это не означает, что все такие входы успешно завершают inference: часть может упасть позже.
- Синтетические две пары (W0,A0), (W1,A1) дают 128 строк вместо 256 строк полного декартова произведения. Полная панель при обучении подтвердила **8 777** пар вместо **8 789**.
- Изменение результата `get_cached_forecast()` меняет сам кэш. Это внутренний программный интерфейс; удалённый клиент через GET напрямую такую мутацию не выполняет.
- При подставленном синхронном inference длительностью 1 секунда таймер event loop на 50 мс сработал через **1,056 секунды**. Это проверка механизма блокировки, не замер времени реального ML-прогноза.

### Честность исторической оценки

Внешний `train.py` содержит разумное разделение: train labels не позже 2026-03-25, early stopping на 2026-03-26–2026-05-28, затем тест 2026-05-29–2026-07-31. Этот путь воспроизводится в сравнении без refit. Ваш holdout fit использует labels не позже origin 2026-05-28; оба метода не получают labels из тестового периода при создании сравниваемых прогнозов, но используют доступное прошлое по-разному.

При этом `evaluate.py` внешнего проекта просто загружает готовую модель и оценивает прошлые срезы, не переобучая её до каждого cutoff. Предупреждение об оптимизме прямо есть в начале файла. Журнал экспериментов, финальный refit и даты показывают, что рекламируемое сравнение по восьми срезам нельзя считать доказательством качества на восьми независимых OOF: финальная модель включает таргеты этих периодов. У вашего проекта есть rolling-origin прогнозы с обучением до соответствующей отсечки; отсутствие Git-истории и уже открытый terminal также ограничивают силу выводов.

### Сколько эффекта даёт одно округление

Дополнительная диагностика без переобучения: `np.rint` вашего сохранённого OOF даёт SMAPE по тексту **31,9832%**, WAPE **75,9040%**, RMSE **0,883344**, Bias **89,2041%**, RMSLE **0,328699**; исполняемый SMAPE при этом ухудшается до **160,3192%**.

То есть простое округление уменьшает текстовый SMAPE вашего прогноза с 47,09% до 31,98% и объясняет большую часть наблюдаемого разрыва с 29,72% внешнего проекта. Оставшийся разрыв относится ко всей совокупности различий моделей, признаков и обучения; отделить эффект одного ансамбля этим опытом нельзя. Это диагностический результат на уже открытом периоде, не основание немедленно менять production-постобработку.

### Практическое решение

- **Для текущей поставки:** оставить вашу реализацию. Внешний код проигрывает по контракту и устойчивости; по текущему исполняемому scorer ваша модель лучше в четырёх компонентах из пяти. Итоговый конкурсный score зависит от официальной нормализации и других участников, его здесь не подменяем собственной суммой сырых метрик.
- **Если организатор подтвердит текстовую SMAPE:** внешний ML-подход становится сильным кандидатом, поскольку SMAPE имеет вес 50%; нужно сравнить его и ваш округлённый вариант на одинаковых rolling-origin окнах. Окончательный общий победитель требует применения подтверждённого scoring protocol.
- **Для развития:** переносить идеи моделей в ваш сервис, сохраняя строгие контракты, manifest, полный каталог и обработку конкурентных запросов.
