# Независимая проверка интеграции

Проверено 18 октября 2026 года. Блокирующих расхождений между текущей моделью, submission, API и проверенным Docker-образом не обнаружено. Полное обучение и тяжёлый POST повторно не запускались: использованы сохранённые протоколы, проверка кода и дополнительные проверки артефактов.

## Артефакты и контракт

- `model/config.json` и загруженный `model/lightgbm.txt` согласованы: schema_version=1, горизонт 64, 45 признаков, 220 итераций. Загрузка сверяет порядок признаков. Каталоги содержат 11 складов и 799 артикулов.
- Фактический заголовок `data/parity/sales.csv` в точности совпадает с 12 обязательными колонками API. Несуществующие в исходной выгрузке `cost_price` и `volume_weight` не требуются. Пропуски категорий допустимы, ключи и целевые числовые поля проверяются отдельно.
- Файл `submission.csv` повторно прочитан и проверен общим валидатором: 562 496 уникальных записей, полный упорядоченный декартов грид, 64 последовательные даты 2026-08-01–2026-10-03, конечные неотрицательные прогнозы.
- Ключи submission совпадают с `data/parity/offline.csv`. Максимальная числовая разница составляет 4.9918806865889565e-09 из-за записи submission с 10 значащими цифрами; это меньше контрактного допуска 1e-7.
- API вызывает общий `src.predict.predict_64`, не обучает модель в запросе, использует фиксированные каталоги и публикует кэш после проверки полного грида. Неуспешный POST сохраняет прошлый кэш. Одновременный POST получает 409; GET удерживает ссылку на завершённый snapshot.

## Связь с проверенным контейнером

Образ `nonton-forecast:verified` имеет ID `sha256:42f395d6d370c3274e0c6ee95a61a2b3f79d8fa6f19d38cc49a376b6f4a32f20`.

В отдельном коротком контейнере с `--network none` посчитаны SHA-256 всех 15 текущих исходных и модельных файлов из `app/`, `src/`, `model/`. Все хэши совпали с локальными файлами; изменений после проверенной сборки в этих файлах не обнаружено. Dockerfile устанавливает `requirements.lock`, копирует только нужный код и модель, запускает один Uvicorn worker. `.dockerignore` исключает исходные датасеты, кэш, отчёты и локальное окружение.

Сохранённый `container_benchmark.json` подтверждает успешный HTTP POST полного входа внутри контейнера без внешней сети: 562 496 строк, максимальная разница с offline 3.552713678800501e-15. Сборка заняла 56.13 с, POST 33.89 с, размер образа 148 784 672 байта, peak memory cgroup 2 429 370 368 байт. Код probe действительно передаёт файлы по loopback HTTP и проверяет ответ; размещение входных CSV в `/tmp` относится только к тестовому запуску и не включает train в образ.

## Границы доказательств

- Полный offline/API и контейнерный паритет проверен на одной одинаковой полной очищенной истории. В локальном API-прогоне повторный POST дал идентичные байты; контейнерный probe выполняет один POST, поэтому отдельная проверка повторного Docker POST не заявляется.
- Полный GET CSV/JSON проверен локально через TestClient; контейнерный probe дополнительно проверяет GET одной пары. Нельзя из этого протокола утверждать отдельный контейнерный benchmark полного JSON.
- Peak RSS локального процесса включает тестовый клиент и сохранённые результаты. Cgroup peak контейнера включает сервер, probe, служебную память и файловый кэш. Эти два значения не являются измерением одной и той же величины и относятся к конкретной машине и одному запуску.
- Вход API с исходными отрицательными остатками или противоречивыми дублями отклоняется с 422. Для измеренных успешных прогонов эти записи явно удалены функцией `clean_stock`; API не выполняет такую очистку молча. Отсутствующие stock остаются неизвестными, продажи без строк принимаются нулевыми по документированному допущению.
- Минимум 180 дней проверяется по включительному диапазону дат каждого файла, а не по числу уникальных дней. Ровно 180 дней истории дополнительно проверены по качеству на одном holdout origin; это не гарантирует одинаковые прогнозы для произвольной короткой и длинной истории.
- Кэш живёт в RAM одного worker и теряется при рестарте. Неизвестные входные ID отклоняются; динамический каталог не реализован. Более поздние остатки исключаются общим ML-кодом на cutoff продаж.
- Инженерный паритет не означает высокого качества спроса: holdout WAPE около 80%, слабые разреженные ряды и stockout-сегменты остаются существенным ограничением. Результат локального критерия не гарантирует место на leaderboard.

Изменений в код, модель или исходные данные при этом обзоре не вносилось.
