# Исправление диапазона categorical encoding до получения метрик

19 октября 2026. Первая попытка обучения завершилась `lightgbm.basic.LightGBMError: bad allocation`. На момент обнаружения `integration/predictions/` не содержал ни одного прогноза, CSV экспериментальных метрик ещё не существовал. Неуспешная попытка не является завершённым fit или доказательством соблюдения бюджета успешных fits. Root сохраняет исходный журнал как `integration/experiments_failed_encoding.txt`.

Первоначальный stable SHA-256 code использовал модуль `2**31-1`. Слишком большой разреженный диапазон categorical IDs — вероятная причина allocation failure LightGBM; точное внутреннее место аллокации не профилировалось. Исправление ограничивает тот же детерминированный хеш модулем **`2**20-1`**. Namespace, состав доступных ID, int32 dtype, признаки, цели, модель, rounds, seed, weights и scoring protocol сохраняются. Оригинальный frozen protocol не переписывается; это приложение объясняет изменение runtime-кодирования перед повторным запуском.

При проверке всех текущих 799 article IDs и 11 warehouse IDs новый модуль не даёт коллизий (максимумы article 1 048 530, warehouse 996 562). Проверка всех IDs здесь диагностическая: runtime-коды определяются каждой строкой независимо, а collision check в helper смотрит только доступные на origin ID. Если новые идентификаторы дадут коллизию, helper явно откажет; он не переставит старые коды в зависимости от будущих ID.

Это исправление исполнимости до просмотра результатов, а не подбор по качеству. Ограничение диапазона не является утверждением универсальной бесколлизионности SHA-кодирования и не обещает качество прогнозов.
